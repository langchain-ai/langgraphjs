Keep Redis store namespaces apart. A namespace's documents were found with a text search over their joined labels, which ignores order, case and punctuation, so `get()`, `search()`, `put()` and `delete()` on `["tenant", "a"]` could read, replace or delete the documents of `["a", "tenant"]`, `["tenant", "A"]` or `["tenant", "a-b"]`. Each document's namespace is now compared exactly before it is returned, replaced or deleted; the index, stored documents and key matching are unchanged. Labels containing `.`, which `put()` already rejects, now read nothing, as does `search([""])`, and vector search narrows by every word of the namespace, falling back to the earlier query if that fails or finds nothing. Since other namespaces' documents are dropped after a page is read, a `search()` page can hold fewer than `limit` items, and a lookup checks at most 100 documents with the same key and words: behind more, `get()` can return `null`, `put()` can write a second copy and `delete()` can leave the document, where earlier versions acted on another namespace's. Upgrade every process that writes to the store, since older versions can still replace or delete other namespaces' documents.
